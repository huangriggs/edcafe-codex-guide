# 在自己的專案接手與維護

將repo放入自己的專案，使用原專案教材來源及年級規則，不複製原作者本機路徑。來源PDF維持唯讀，自編素材另存；文件寫來源、年級、章節、版本及QA。

可在原AGENTS.md追加：

```markdown
## Edcafe教學工具
涉及Edcafe時，先讀工具/edcafe-codex-guide/skills/edcafe-operations/SKILL.md，依目的載入教學顧問指南或操作索引。
介面以當前畫面核對；新成果需保存並測試，學生與教師內容分離；完成後更新本專案handoff.md。
```

對話結束交接範例：

```markdown
## YYYY-MM-DD：任務名稱
- 需求／年級／章節：
- 來源：檔名＋PDF頁碼；自編部分：
- 產出位置／版本：
- 平台保存結果與可見性：
- QA：實際哪些通過；哪些僅介面或未測：
- 偏離／阻塞及下一步：
```

新發現先記實測日期及環境。操作索引、JSON status與顧問指南矩陣要一致；參考副本更新時檢查差異，避免舊版本蓋回新版本。只修改任務必要文件。

例：收到下載檔、開啟無誤才把Word下載由待重測升為已實測；教師Preview成功不能將正式學生提交升級為通過。速度優化要有基準測量，目前沒有固定倍率證據。
